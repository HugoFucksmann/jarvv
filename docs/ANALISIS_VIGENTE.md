# Análisis vigente de JARVIS

Consolidación verificada de lo que sigue siendo cierto y útil del análisis del proyecto (`docs/analisis/*` y `docs/JARVIS_EVALUACION.md`). **Fuente de verdad:** `src/` y `eval/` del repositorio; lo abierto se lleva en [`docs/PENDIENTES.md`](PENDIENTES.md) y el historial de cambios en [`CHANGELOG.md`](../CHANGELOG.md).

Actualizado el 2026-11-14. Cada afirmación sobre el comportamiento actual, umbrales y símbolos se verificó contra el código de ese día.

**Etiquetas:** **[D]** necesita decisión · **[V]** por medir con modelos reales o uso real · **[C]** depende de algo externo (MCP vivo, hardware, Ollama) · **[B]** construible ya, sin decisión.
**Estados (sección 3):** ✅ hecha · ⚠ hecha parcial / apagada por defecto · ⏸ en pausa / abierta aparte · ❌ descartada o revertida.
**Plataforma:** JARVIS apunta a Windows + PowerShell (`src/core/policy/commandRules.ts` contempla POSIX solo como precaución; la terminal no se ofrece fuera de Windows).

## 1. Cómo funciona hoy (estado real)

### Runtime, configuración y límites base
- **Modelos y configuración (`src/core/config.ts`, `jarvis-config.json`):** `DEFAULT_CONFIG` (`src/core/config.ts:121-164`) define `qwenModel: "qwen3.5:4b"`, `decisionModel: "d3:2b"`, `qwenNumCtx: 16384`, `decisionMaxContext: 16384`, `qwenMaxTokens: { arguments: 2048, plan: 4096, replan: 4096, final: 2048 }`, `thinking: false`, `modelKeepAlive: "30m"`, `autoMode: false`, `approvalTiers: false`, `webSearchUseJudge: true`, `retentionDays: 30`, `refsDir: "data/refs"`, `traceEnabled: true`. El archivo `jarvis-config.json` activo en el repositorio activa las variantes sin visión (`qwen3.5:4b-text`, `d3:2b-text`), `autoMode: true` y `approvalTiers: true`.
- **Precalentamiento y caché (`src/core/models/warmup.ts`, `src/core/engine/env.ts`):** `warmUpModels` (`src/core/models/warmup.ts:39-53`) consulta al arrancar primero Decisión (`warmup` `noul`) y luego Qwen (`max_tokens: 1`, `reasoning_effort: "none"`) enviando `modelKeepAlive` como `keep_alive`. Dentro de cada tarea, `memoizeDecision` (`src/core/engine/env.ts:35-60`) cachea por entrada serializada (`stage + JSON.stringify(input)`) todas las respuestas válidas de `IActionDecision` (no `FragmentJudge.score`).
- **Reintentos y `thinking` (`src/core/budget.ts`, `src/core/models/stageRequests.ts`, `src/core/models/qwen.ts`):** Qwen reintenta una vez dentro de `dispatchValidated` (`BUDGET.invalidResponseRetries: 1`, `src/core/models/qwen.ts:484`, factor `1.5x` tokens, temperatura ≥ `0.3`). Todas las llamadas del motor a `queryModel(..., 0)` pasan `0` reintentos, incluyendo todas las consultas a Decisión (`DN-3.4`). `config.thinking` gobierna solo `final_response` (`src/core/models/stageRequests.ts:149-150`, con `retryThinking: false`); `plan`/`replan` fijan `thinking: true` y `arguments`/`question`/`pending` fijan `false`.
- **Topes del motor (`src/core/budget.ts:38-75`, `src/core/engine/limits.ts:30-150`):**
  - Tarea / ítem: `maxSteps: 20`, `maxReplans: 3`, `maxEscalations: 2`, `maxItemFailures: 2`, `MAX_REOPENS = 2` (`src/core/engine/runTask.ts:72`).
  - Paso (`STEP_RULES` en orden de precedencia, `src/core/engine/limits.ts:121-129`): `maxRepeatsPerStep: 2` → `repeat_blocked`; `maxUserRejectionsPerStep: 2` → `user_rejected`; `maxDeniedPerStep: 2` → `denied`; `maxReviewRejectionsPerStep: 2` → `review_rejected`; `maxVerifyRejectionsPerStep: 2` → `verify_rejected`; `maxCallsPerStep: 6` (ejecuciones reales, `askFirst: true`) → `call_cap`; `maxAttemptsPerStep: 10` (toda llamada registrada salvo `user_rejected`, `askFirst: true`) → `call_cap`. Además: `maxNotAccomplishedPerRoute: 2` (`src/core/engine/limits.ts:147`), `maxQuestionsPerStep: 1`, `maxProcessPromptsPerStep: 3`.
